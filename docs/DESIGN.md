# SoundWeight Graph — 멀티트랙 오디오 하이라이트 탐지기 설계서

> 문서 버전: 0.1.0 / 작성일: 2026-10-23  
> 상태: **구현 지시용 설계 초안** — 실제 구현·테스트·배포는 아직 수행하지 않음  
> 대상: Windows 10/11 x64, OBS 등으로 제작된 다중 오디오 트랙 MP4 녹화본

## 0. Work 모드에 전달할 지시

이 문서를 제품 요구사항 및 구현 기준으로 사용해 **실행 가능한 Windows 데스크톱 프로젝트**를 구현한다. 단순한 목업이나 UI만 만들고 완료로 간주하지 않는다.

1. 먼저 설계서를 읽고 모듈별 구현 계획을 세운다.
2. 핵심 순서: **MP4 트랙 탐색 → 오디오 특징값 추출 → 트랙 제외·가중치 반영 → 점수 그래프 → 캐시 → 단일 EXE 배포**.
3. 한 단계가 끝날 때마다 빌드/테스트를 실행하고 실제 결과를 확인한다. 문제가 생기면 추정으로 완료 처리하지 말고 수정한다.
4. 최종 산출물은 전체 소스, 빌드 방법, 테스트, 가능하다면 **실제 `SoundWeightGraph.exe` 한 개**다. 실행 파일 생성·실행을 검증하지 못했다면 그 사실을 명확하게 남긴다.
5. 아래에서 `MUST`는 MVP 필수, `SHOULD`는 우선 권장, `LATER`는 후속 기능이다. 개발 환경상 변경이 불가피하면 이유와 대안을 문서화한다.
6. 배포되는 완성품은 인터넷 연결이나 런타임/SDK/FFmpeg 설치 없이 실행되어야 한다. **사용자가 ZIP을 풀거나 설치 마법사를 진행하는 절차도 없다.**

## 1. 프로젝트 목적

스트리머가 2~5시간의 녹화 영상을 처음부터 모두 확인하지 않아도, **오디오가 활발해지거나 여러 트랙의 반응이 몰리는 시간대**를 시각적으로 찾게 해 주는 도구다.

입력: `*.mp4`에 포함된 1개 이상의 개별 오디오 스트림(주 대상: OBS의 최대 6개 오디오 트랙).  
출력: 영상 전체 시간 축 위의 **0~100 활동 밀집도 점수 그래프**, 트랙별 활성화·가중치 설정, 마우스 위치의 정확한 시각 표시.

**중요한 의미 구분**: 점수가 높다는 것은 *소리의 변화와 다중 트랙 반응이 많이 발생했다*는 뜻이지, 장면의 재미나 편집 품질을 인공지능이 판단했다는 뜻이 아니다. UI에서는 쉽게 이해되도록 '하이라이트 후보 점수'로 표시하되 설명에는 이 한계를 명시한다.

### 성공 기준

- 사용자: `SoundWeightGraph.exe` **하나를 더블클릭**, MP4 파일을 선택/드래그하면 트랙이 표시된다.
- 사용자는 불필요한 트랙을 끄고 각 트랙의 가중치를 조정할 수 있다.
- 녹화 파일의 시간대별 후보 점수 그래프가 나온다.
- 체크박스/가중치를 변경하면 **MP4 디코딩 없이** 저장된 특징 데이터로 그래프가 즉시 재계산된다.
- 빈 트랙이 꺼졌다는 이유만으로 다른 트랙의 점수가 희석되지 않는다.
- 인터넷 접속·로그인·클라우드 업로드는 하지 않는다.

### 명시적 비목표 (v0.1.0)

- 실제 영상 자동 편집·컷 편집·렌더링
- 음성 인식(STT), LLM, 웃음/비명 음향 분류 AI
- 게임 화면 이해, 감정·재미 판정, 장면 자동 제목 생성
- 프리미어 프로젝트/마커 자동 내보내기
- 설치 마법사, 브라우저 기반 웹서비스, 외부 백엔드
- 앱 내부 영상 재생(추후 추가 가능)

## 2. 사용자 경험과 UI

### 초기 화면

- 상단: 파일 선택 버튼, MP4 파일 드래그&드롭 영역, 파일명 및 영상 길이.
- 왼쪽 또는 하단: 트랙 목록(발견한 오디오 스트림 수만큼 생성; 6개로 고정하지 않음).
- 중앙: 전체 시간 축(가로) / 활동 밀집도 점수 0~100(세로)의 꺾은선 그래프.
- 하단: 분석 상태와 진행률, 오류/경고, 마우스 커서의 `HH:MM:SS.mmm` 시각 및 점수.

### 트랙별 컨트롤 (MUST)

| 항목 | 기본값 | 동작 |
|---|---|---|
| 사용 여부 | 내용이 있는 독립 트랙: ON | OFF면 기본점수·동시활동 계산에서 완전 제외 |
| 가중치 | 1.00 | 슬라이더/숫자 입력, 범위 `0.00 ~ 3.00`, 간격 `0.25` |
| 표시 이름 | `오디오 1`, `오디오 2`… | `title` 메타데이터를 읽을 수 있으면 함께 표시 |
| 스트림 정보 | 자동 | 코덱, 채널, stream index, 추정 유효 활동 비율 등 |
| 분석 상태 | 미분석/분석 중/완료 | 진행 과정과 오류 표시 |
| 빈 트랙 감지 | 자동 제안 | 신호가 사실상 없다면 OFF 권장, 사용자가 재활성화 가능 |

**주의:** OBS는 1번 트랙에 전체 믹스, 2~6번에 개별 소스를 넣는 경우가 있다. 이런 경우 중복 점수 상승을 막기 위해 1번을 '믹스 가능성 있음'으로 표시하고 기본 제외를 제안한다. 단, 모든 파일의 1번이 전체 믹스라고 단정하지 말 것. '전체 믹스' 유형은 사용자가 지정할 수 있게 하고, 확정되지 않은 자동 추정은 강제로 적용하지 않는다.

### 그래프 필수 상호작용 (MUST)

- 마우스 휠 확대·축소, 드래그로 좌우 이동, 전체 보기 복귀.
- 그래프에 마우스를 올리면 해당 시간과 점수 표시.
- 클릭한 시각을 `HH:MM:SS.mmm`로 표시하고 **클립보드에 복사**할 수 있게 한다.
- 데이터가 너무 조밀할 때도 UI가 멈추지 않도록 화면 해상도에 맞춘 다운샘플 렌더링을 제공한다. 원본 점수 배열은 유지한다.
- 트랙을 꺼도 그래프가 사라지지 않아야 하며, 모든 트랙을 끈 경우 '분석 대상 트랙 없음'을 표시하고 빈 그래프로 처리한다.

### 화면 상태

`파일 미선택 → 파일 조사 → 트랙 설정 → 오디오 분석 중 → 그래프 표시`; 분석 중에는 취소 가능. 파일 변경 시 이전 분석을 적절히 취소하고 새로운 상태로 전환한다.

## 3. 기술 스택 / 단일 EXE 배포

| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 | C# | Windows 데스크톱 앱, 유지보수 |
| 런타임 | .NET 10, `net10.0-windows` | Self-contained single-file publish |
| UI | WPF + MVVM | 네이티브 Windows 데스크톱 UI |
| 그래프 | ScottPlot 5 (`ScottPlot.WPF`) | 대용량 시간 그래프의 확대·이동 |
| 미디어 조사 | `ffprobe` | MP4 스트림 메타데이터 탐색 |
| 디코딩 | `ffmpeg` | 선택된 오디오 스트림을 PCM으로 변환해 파이프로 수신 |
| 설정/캐시 | `System.Text.Json` | 외부 DB 불필요 |
| 테스트 | xUnit 또는 동급 테스트 도구 | 점수 엔진, 트랙 제외, 캐시/예외 검증 |

### 배포 계약: 사용자에게 파일 하나만 전달한다 (MUST)

최종 배포물:

```text
SoundWeightGraph.exe
```

사용자 입장에서 EXE 외에 `ffmpeg.exe`, `ffprobe.exe`, DLL, SDK, 설치 파일, ZIP, VC++ 재배포 패키지, 별도 런타임 설치는 **필요 없어야 한다**.

권장 방식:

1. 앱은 **Self-contained + PublishSingleFile**로 빌드한다. WPF/SkiaSharp 등의 네이티브 의존성을 단일 번들에 넣기 위해 `IncludeNativeLibrariesForSelfExtract=true` 사용 여부를 검증한다. `PublishTrimmed=false`를 기본으로 둔다.
2. 허가된 재배포용 `ffmpeg.exe`/`ffprobe.exe` 바이너리를 빌드 리소스로 **EXE 내부에 임베드**한다. 실행 파일 자체를 사용자가 볼 수 있도록 별도 배포하지 않는다.
3. 실행 시 필요한 경우 프로그램이 `%LOCALAPPDATA%\SoundWeightGraph\tools\<version>\` 등에 내부 바이너리를 **자동으로 추출**하고 SHA-256 등으로 일치성을 검사한 뒤 사용한다. 앱 종료 후 재사용 가능. 사용자가 수동으로 압축 해제하는 것이 아니다.
4. .NET 번들의 네이티브 추출 또한 내부적으로 발생할 수 있다. **'EXE 하나를 전달한다'와 '디스크에 절대 다른 파일이 생성되지 않는다'는 다른 요구**임을 인지한다.
5. 실행에 네트워크 다운로드가 필요해서는 안 된다. 파일 읽기·앱 데이터 기록은 일반 사용자 권한으로 수행한다.
6. `dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:PublishTrimmed=false`를 출발점으로 사용한다. 빌드 후 실제 산출물 수와 깨끗한 Windows PC에서의 실행 여부를 확인한다.
7. FFmpeg 리소스는 검증된 빌드만 사용한다. FFmpeg의 LGPL/GPL 선택 옵션과 **재배포 고지·소스 제공 등 해당 라이선스 준수**를 확인하고, 라이선스 내용과 빌드 정보를 앱 내 '오픈소스 고지' 메뉴에서 볼 수 있게 한다. 라이선스 확인 전 미검증 바이너리를 임의로 번들링해 외부 배포하지 않는다.
8. 서명되지 않은 EXE는 Windows SmartScreen 경고가 발생할 수 있다. 실제 배포 시 코드 서명 여부를 별도 결정하고, **무경고 실행을 보장한다고 주장하지 않는다**.

출시 대상은 우선 **Windows x64 단일 EXE**다. ARM64/다른 OS는 별도 산출물로 후속 지원한다.

## 4. 미디어 처리 파이프라인

```text
MP4 파일 선택
    ↓
ffprobe로 format/stream 메타데이터 파악
    ↓
오디오 트랙 목록 및 활성화/가중치 UI 구성
    ↓
ffmpeg로 선택된 각 스트림 디코딩 (16 kHz, mono, Float32 PCM)
    ↓
0.5초마다 RMS(dBFS), 피크, 갑작스러운 상승량 등 특징 추출
    ↓
각 스트림별 시간 정렬된 '원시 특징 배열' 저장
    ↓
시간별 상대 활동량 a_i(t) ∈ [0,1] 계산
    ↓
사용자 가중치·제외 설정 적용 및 다중 트랙 반응 점수 결합
    ↓
약한 그래프 스무딩 → 0~100 점수 그래프
```

### `ffprobe` 예시

```bash
ffprobe -v error -show_format -show_streams -of json "recording.mp4"
```

- `codec_type == "audio"` 스트림만 골라 **실제 스트림 인덱스(`index`)**와 **UI상의 오디오 순번**을 별도로 보관한다. 영상 스트림 때문에 둘이 달라질 수 있다.
- `format.duration`이 없거나 부정확한 파일을 대비해 스트림 길이/디코딩된 실제 길이를 활용한다.
- 파일명은 한글·공백·특수문자 포함을 지원한다. `ProcessStartInfo.ArgumentList`를 사용하고 셸 문자열 연결을 피한다.

### `ffmpeg` 예시 (한 스트림씩)

```bash
ffmpeg -nostdin -v error -i "recording.mp4" -map 0:1 -vn -ac 1 -ar 16000 -f f32le pipe:1
```

`0:1`은 예시이며 **선택된 ffprobe의 실제 stream index**로 바꿔야 한다. ffmpeg를 별도 프로세스로 실행하되 디코딩 결과는 표준 출력으로 스트리밍 처리하고, 표준 오류는 따로 비동기 소비한다. 잘못된 파일에 대한 대기·프로세스 종료·사용자 취소를 구현한다.

**시간 동기화 중요**: 일부 스트림은 시작 시각(start_time), PTS, 편집 리스트가 다르다. 단순히 각 PCM의 첫 샘플을 `t=0`으로 놓으면 여러 트랙을 잘못 겹칠 수 있다. 먼저 일반적인 OBS 생성 MP4를 지원하고, 오프셋이 있는 테스트 파일로 검증해 필요한 경우 PTS/패딩 기반 정렬을 추가한다. **시간 정렬이 검증되지 않은 상태로 동시활동 점수를 신뢰하지 말 것.**

- 원본 영상 트랙을 디코딩하지 않는다. 원본 MP4를 수정하지 않는다.
- 장시간 파일도 PCM 전체를 메모리에 보관하지 않고 **작은 청크로 순차 처리**한다.
- 처음엔 안정성을 위해 오디오 스트림을 순차 디코딩하고, 필요하면 나중에 병렬 처리한다.
- 재현성 확보를 위해 분석 샘플레이트, 구간 폭, 알고리즘 버전을 캐시에 포함한다.

## 5. 점수 엔진 (MVP의 핵심)

### 5.1 시간 프레임과 원시 특징

- 기본 프레임 길이: `Δt = 0.5 s` (설정 파일 또는 상수로 변경 가능).
- 각 프레임에 트랙별 `RMS`, `peak`, `dBFS`, 유효 샘플 수를 계산한다.
- RMS: `sqrt(mean(x[k]^2))`; `dBFS = 20*log10(max(RMS, epsilon))`.
- 소리가 거의 없거나 전체가 일정한 트랙에 대해 비정상적으로 큰 상대 점수가 나오지 않도록 **절대 무음 기준 + 상대 변화 기준을 함께 적용**한다.
- 일정한 BGM/엔진 소음은 보통의 상태로 간주되어 하이라이트 점수를 지속적으로 밀어 올리지 않도록 한다.

### 5.2 트랙별 활동도 `a_i(t)`

각 트랙의 오디오 변화 패턴을 독립적으로 0~1로 정규화한다. **'크기' 하나만이 아니라 '평소 대비 변화'를 본다.** 최초 알고리즘 권장 구성:

1. **Energy deviation**: 주변 30~60초의 강건한 중앙값/분위수와 비교한 상대적 에너지 상승.
2. **Onset**: 직전 1~3초에 비해 급작스럽게 소리가 상승했는지.
3. **Burst density**: 최근 약 5초 안에 작은 반응이 얼마나 반복됐는지.

권장 시작 가중: `activity = clamp(0.45 × deviation + 0.35 × onset + 0.20 × burst_density, 0, 1)`.

이 계수는 검증으로 조정할 **초기 휴리스틱**이며 고정된 진실이 아니다. 입력에 강한 컴프레서/노이즈 게이트가 걸린 경우 원시 음량만으로 웃음과 대화를 구분할 수 없다는 한계도 있다.

#### 무음·빈 트랙 판단

- **디코딩 가능 여부**, 실제 신호의 최대치/총 에너지, 유효 구간 비율을 함께 관찰한다.
- 완전 무음 또는 사실상 무음이면 '비활성 권장'으로 표시한다.
- 단순히 조용하다는 이유만으로 중요 마이크를 자동 삭제하지 않는다. 사용자 선택으로 ON 가능.
- 빈 트랙은 디폴트 OFF 후보이며 점수 분모에서 제외한다.

### 5.3 가중 평균 점수

활성화되고 가중치가 0보다 큰 트랙의 집합을 `A`로 둔다.

```text
B(t) = Σ(i ∈ A) [ w_i × a_i(t) ] / Σ(i ∈ A) w_i
```

- `w_i`: 사용자 설정 가중치 `0~3`, 기본 `1`.
- OFF 트랙/가중치 0 트랙은 **분자, 분모, 동시반응 계산에서 전부 제외**한다.
- `A`가 비어 있으면 계산을 하지 않고 **'분석 대상 없음'** 상태로 표시한다(0으로 나누지 않음).
- 분석되지 않았거나 오류가 난 트랙은 0점 오디오로 오인하지 않고 별도 오류 상태로 취급한다.
- 미사용 트랙이 많아도 전체 점수가 희석되지 않는다.

예시:

| 트랙 | 활성도 (0~100) | 가중치 | 포함 |
|---|---:|---:|---|
| 마이크 | 80 | 2.0 | YES |
| 디스코드 | 90 | 1.5 | YES |
| 게임 | 40 | 0.5 | YES |
| 빈 트랙 | 0 | 1.0 | NO |

`B × 100 = (80×2 + 90×1.5 + 40×0.5) / (2+1.5+0.5) = 78.75점`.

### 5.4 여러 트랙의 '몰림' 점수

같은 프레임에만 이벤트가 딱 겹쳐야 하는 것은 아니다. 게임 소리 이후 2초 뒤 마이크, 1초 뒤 디스코드 반응이 발생하는 상황도 감지한다.

```text
d_i(t) = max{ a_i(τ) | τ ∈ [t-3초, t+3초] }

C(t) = Σ(i<j, i,j∈A) [ w_i × w_j × min(d_i(t), d_j(t)) ]
       / Σ(i<j, i,j∈A) [ w_i × w_j ]
```

- **포함된 트랙이 2개 미만**이면 `C(t)=0`.
- 중복/전체 믹스 트랙은 사용자가 기본 제외하도록 유도. 중복 검출·자동 제외는 후속 기능.
- 양쪽 트랙에서 변화가 함께 관측될 때 점수가 커지되, 시간 여유 `±3초`를 허용한다.
- `±3초`는 예비값이며 실제 라프사의 데이터로 비교해야 한다.

최종 점수는 다음을 기준으로 한다.

```text
S(t) = 100 × clamp( B(t) + 0.25 × C(t) × (1 - B(t)), 0, 1 )
```

특징: **개별 트랙만 활성인 경우에도 점수가 나올 수 있고**, 다중 반응이 몰린 구간은 소폭 가산된다. 한 트랙만 선택해도 최고점의 인위적인 상한(예: 80점)이 생기지 않는다. 동시반응 보너스가 0~100 범위를 넘지 않는다.

**주의:** C의 분모는 모든 유효 트랙 쌍의 가중치 합이고, 꺼진 트랙은 여기서도 제외한다. 트랙 수가 달라져도 점수 해석이 비교적 일관되도록 하는 초기 규칙이다. 전체 믹스를 켜면 같은 소리를 중복 감지할 위험이 있다.

### 5.5 스무딩 및 후보 탐색

- 최종 `S(t)`의 너무 잔잔한 흔들림만 완화하는 **1~3초 이동 평균 또는 중앙값 필터**를 사용한다. 과도한 평활화로 짧은 비명/웃음이 사라지지 않도록 원시·스무딩 점수를 구분 보관한다.
- MVP 필수 산출물은 **그래프 전체**다. 상위 N개 구간 목록/컷 추천은 후속 기능이다.
- 높은 값들이 집중된 여러 프레임은 추후 하나의 후보 이벤트로 병합할 수 있도록 구조만 열어 둔다.

### 5.6 재계산 규칙

**디코딩/특징 추출 단계는 가중치 변경과 무관**해야 한다.

- 파일을 최초 분석하면 `TrackFeatures[]`가 만들어진다.
- 트랙 체크박스/가중치 변경 → `ScoreCalculator`만 재실행 → 그래프 갱신.
- 원래 MP4를 다시 열거나 ffmpeg를 재실행하지 않는다.
- UI에서 빠르게 값을 변경해도 오래된 계산 결과가 새 그래프를 덮어쓰지 않도록 계산 세대 번호/취소 토큰으로 보호한다.

## 7. 로컬 캐시와 사용자 설정

기본 경로 예시:

  cache\
  config\settings.json

### 캐시

- 키: 파일의 정규화 경로 + 파일 크기 + 수정 시각 + 특징 추출 알고리즘 버전 + 분석 옵션 버전. 필요 시 더 강한 fingerprint로 강화.
- 저장 내용: 트랙 구조, 시간대별 원시 오디오 특징값, 정규화 결과, 분석 버전.
- 점수 가중치/ON·OFF는 캐시 무효화 요인이 아니다. **빠른 재계산**으로 처리한다.
- 파일이 변경되거나 분석 버전이 바뀌면 캐시 무효화.
- 잘못된 캐시/불완전한 캐시가 있으면 경고 후 재분석 가능해야 한다.
- 사용자가 '캐시 지우기'를 선택할 수 있도록 한다.

### 설정

- 마지막으로 사용한 가중치, 트랙 역할 프리셋, 그래프 옵션 저장.
- 같은 파일을 다시 열면 해당 파일에 대한 트랙 활성화 및 가중치를 복원한다.
- 다른 파일에 동일 트랙 순번을 맹목적으로 적용하지 말고 사용자에게 확인하거나 프리셋을 선택하도록 한다.

## 8. 오류/보안/성능

### 오류 상황 (MUST)

- MP4가 아님 / 지원하지 않는 코덱 / 손상 파일 / 오디오 스트림 0개.
- 파일 접근 거부, 파일 이동·삭제, 디스크 부족, 미디어 도구 추출 실패.
- 재분석 도중 취소/앱 종료, ffmpeg 프로세스 비정상 종료.
- 스트림별 분석 일부 실패. '조용한 트랙'과 '분석 실패한 트랙'을 혼동하지 않는다.
- `NaN`/무한대/분모 0이 그래프에 전달되지 않도록 검증한다.

### 보안·프라이버시 (MUST)

- 분석은 **100% 로컬**. 파일 업로드, 텔레메트리, 외부 API 호출 없음.
- 미디어 파일 경로를 셸 명령 문자열로 직접 합치지 않는다. FFmpeg의 표준 입출력 파이프 사용.
- 앱 내부 도구 파일은 앱 전용 사용자 디렉터리에 버전별로 저장, 해시 검증, 타 사용자 쓰기 가능 위치에서 실행하지 않는다.
- 원본 MP4는 읽기 전용 취급. 분석 과정에서 수정·이동하지 않는다.
- 디코더는 신뢰할 수 없는 미디어를 처리하므로 FFmpeg 보안 패치 업데이트 정책을 정한다.
- 로그에는 민감한 녹취 내용을 남기지 않으며, 필요하지 않으면 전체 파일 경로도 익명화한다.

### 성능 (MUST)

- 수 시간 MP4 분석 중에도 GUI 응답 유지, 진행/취소 작동.
- Float32 PCM 전체 적재 금지. **청크 스트리밍 + 프레임 특징 축약**.
- 그래프는 수만 개 프레임도 다루도록 viewport 기반 렌더링 최적화.
- 가중치 변경 시 재디코딩이 없음을 자동 테스트나 계측으로 검증.
- 전력/CPU 소모는 초기 구현 이후 대표 녹화본으로 벤치마크하고, 성능 수치를 추측해 홍보하지 않는다.

## 9. 테스트 기준 / 완료 판정

### A. 점수 엔진 단위 테스트

1. **빈 트랙 제외**: 신호 `[0,0,…]`의 트랙을 추가·OFF해도 기존 결과가 정확히 같다.
2. **가중 평균**: 예시 `80,90,40 / 2,1.5,0.5` 결과 기본 점수 `78.75`.
3. **가중치 0**: 해당 트랙을 OFF한 경우와 같은 결과.
4. **전체 OFF**: 예외/NaN 없이 '분석 대상 없음'.
5. **단일 트랙**: 동시반응 점수 0이지만 0~100 기본 점수 정상 출력.
6. **두 트랙 동시 상승**: 단독 상승 때보다 동시반응 보너스가 커진다(기본 점수 차이와 분리해 검증).
7. **지연 반응**: 2초 간격으로 발생한 두 트랙의 이벤트가 `±3초` 윈도우에서 결합된다.
8. **음악 지속 재생**: 소리 크기가 높은 상태라도 수 분간 거의 일정하면 고득점이 고정되지 않는다.
9. **무음/극저음**: 정규화 폭주, 0으로 나누기, 수치 오류가 없다.
10. **가중치만 변경**: 특징값 추출기/FFmpeg 호출 횟수가 증가하지 않는다.

### B. 통합 테스트용 인공 MP4

- `OBS_6tracks.mp4`: 트랙 1 전체 믹스, 2 마이크, 3 디스코드, 4 게임, 5 빈 트랙, 6 BGM.
- `burst_lag.mp4`: 2초 간격으로 분리된 음향 이벤트.
- `steady_background.mp4`: 음악/게임음은 계속 크지만 반응은 없는 장면.
- `silent.mp4`: 완전 무음 스트림.
- `one_audio.mp4`: 오디오 트랙 하나만 존재.
- `offset_streams.mp4`: 오디오별 시작 PTS가 다른 영상, 시간 정렬 검증.
- `corrupt.mp4`: 읽을 수 없거나 손상된 파일.
- 한글·공백·특수문자가 들어간 경로의 영상.

테스트 파일은 FFmpeg 등으로 생성할 수 있되, 회귀 검증에 필요한 fixture 생성 스크립트와 기대 결과를 저장한다.

### C. 실제 배포 테스트

- [ ] `dotnet publish`가 오류 없이 성공.
- [ ] 전달용 디렉터리에 **EXE 한 개**만 존재하며 이 파일만으로 실행 가능.
- [ ] **SDK/.NET Runtime/FFmpeg를 따로 설치하지 않은 깨끗한 Windows 10/11 x64 환경**에서 실행 확인.
- [ ] 인터넷 연결을 끈 상태로 MP4 열기·분석·그래프 갱신 가능.
- [ ] 임의 위치(바탕화면, 다운로드, 한글 경로)에서 실행 가능.
- [ ] FFmpeg 도구 자동 추출/재사용/업데이트/실패 처리가 정상.
- [ ] 트랙 OFF/가중치 변경 후 재분석 없이 그래프 변경.
- [ ] 수 시간 녹화본 분석 중 취소해도 프로그램과 자식 프로세스가 정상 종료.
- [ ] 라이선스 정보 및 외부 코드 고지 확인.
- [ ] 코드 서명 및 SmartScreen 경고 여부를 테스트 결과에 명시.

### Phase A — 미디어 탐색

- WPF 창, 파일 선택·드래그&드롭.

### Phase B — 오디오 특징 추출

- 트랙별 청크 PCM 수신, RMS/dBFS/피크/변화량 등 분석.

**완료 조건**: 6트랙 샘플에서 트랙별 특징값을 끝까지 얻는다.

### Phase C — 점수와 시각화

- 상대 활동도, 포함 트랙 가중 평균, 다중 트랙 몰림 점수.
- 0~100 그래프, 마우스 시각 확인, 그래프 탐색.
- OFF/가중치 변경에 따른 **즉시 재계산**.

**완료 조건**: 모든 점수 단위 테스트 통과, 실제 녹화본에서 차트 표시.

### Phase D — 캐시 및 배포 검증

- 로컬 특징 캐시/파일별 설정, 캐시 무효화.
- 배포용 single-file publish 자동화, 재배포 라이선스 점검.
- Windows 깨끗한 환경에서 EXE만 복사해 실행·분석 테스트.

**완료 조건**: 'EXE 하나 더블클릭' 경험이 테스트로 확인됨.

## 11. 후속 확장 후보 (v0.2+; 이번 구현 대상 아님)

- 점수 상위 구간 목록, 앞뒤 여유 초 설정, 편집 후보 CSV 출력.
- 전체 믹스와 독립 트랙의 유사도를 이용한 중복 트랙 감지.
- 트랙별 곡선을 겹쳐 보이기, 사용자 지정 색상, 구간 북마크.

- 영상 미리보기·타임코드 점프, 프리미어 마커/편집 타임라인 내보내기.
- 스트리머별/방송 장르별 가중치 프리셋 및 실제 편집 결과 기반 튜닝.

## 12. 설계상 주의사항 요약

1. **'반응 밀집도'와 '재미'는 다르다.** 의미 있는 조용한 장면을 놓칠 수 있다.
2. **사용자가 끈 트랙은 어떠한 점수 계산에도 관여하지 않는다.** 무음은 평균에 포함하지 않는다.
3. **가중치를 변경할 때 영상을 재디코딩하지 않는다.** 오디오 특징값과 점수 결합을 분리한다.
4. **오디오 트랙마다 실제 시간 위치가 다를 수 있다.** PTS·오프셋 정렬 검증은 필수다.
5. **EXE 단일 전달 ≠ 실행 중 임시 파일을 단 한 개도 생성하지 않음.** 내부 자동 추출은 허용하되 사용자의 추가 작업은 없어야 한다.
6. **OBS의 트랙 1은 종종 전체 믹스**다. 중복 집계 위험을 안내하되 무조건 제외하지 않는다.
7. 실제 MP4 처리·단일 EXE 실행이 검증되기 전에는 **구현 완료라고 보고하지 않는다.**
